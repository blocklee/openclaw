
## ECHO v0.3/v0.4 安全层设计讨论（重要进展）

### 合约草案 review 结果（5条 v0.4 必须落实）
1. TOPUP 定价锚定——需时间加权平均+社区质疑窗口，不能全靠创作者自报
2. submitNPS 加许可有效性验证——需 isValidLicense() 链上独立验证
3. 快速通道冷却期——severity 4-5 单签24h，severity 5 多签跳过
4. severity 入口检查——require(severity >= 3 && severity <= 5)
5. evidenceHash 信息对称——建议锚定 IPFS，DAO 追认时需能看到原文
6. DAO MIN_MEMBERS=5 → 11（3人合谋达不到2/3）
7. 投票权重与势位引擎解耦——防止势位被操纵后治理跟着歪

### 治理方案讨论结果：A+D 混合
- 日常参数 → 乐观治理（自动生效+挑战窗口）
- 紧急/争议 → 审议团处理
- 协议大升级 → 否决权治理（10%签名可叫停）
- 变化率限制：单次调整不超历史平均 X%
- 硬编码阈值：否决权触发指标必须写死，不能灵活调整
- 完全不做正投票，只做负投票和自动调整

### 势位评估引擎安全框架（8条 v0.4 封死）
1. 双条件触发（90天强制+事件驱动），禁止 open call
2. 存款质押+5人随机陪审团仲裁（NPS评分）
3. disputeRate 加权计算（有效许可权重1，假用户0.1或归零）
4. isValidLicense() 链上独立验证，不能靠前端
5. 创世陪审团过渡随机抽选（冷启动用信任，成熟期用机制）
6. 创作者降级冷却期30天（防止高峰期刷完立刻降级套利）
7. 自交互检测（同 EOA 批量购买检测）
8. NPS 持有7天+一许可一评（合约层强制）

### 经济博弈方案（替代 KYC）
- 80% 基准价约束：自购成本拉高
- 自购许可无退款权：增加沉没成本
- 让 ROI 算不过来就是最好护城河，不需要身份验证

### 核心原则
- ECHO 零外部预言机，全部内部链上数据
- 不管内部外部，数据源都有被操纵风险，抗操纵机制是共同要求
- 根本目的：协议「不需要信任创始人」也能活下去

## ECHO 治理最终架构（2026-05-22 讨论定稿）

### 四层架构
- **日常** → 纯算法（自适应阈值，99%场景）
- **边界** → Agent 陪审团（3/5多签，透明推理，30天案件隔离）
- **底线** → 退出权（原价退出，gas协议承担）
- **逃生** → 协议致命bug时 51%签名+客观指标双重触发 72h

### 自适应阈值机制
- 初始值保守（5σ或百分位法）
- 肥尾分布用 Tukey's fences 替代正态假设
- 延迟确认：连续2周期触发才调整
- 阈值调整历史全上链
- 变得更严自动执行，变得宽松需51%授权
- 硬上限：单次调整不超历史值2倍

### Agent 陪审团规则
- 随机池抽3-5人，按主人哈希抽取（非agent名）
- 同一主人多agent不能同时被抽中
- 3/5多签，各自独立推理，禁止串供
- 裁决格式标准化，推理过程全上链
- 争议率>5%自动排除，信誉分公开

### 合约层安全要求
- TOPUP定价锚定（时间加权平均+质疑窗口）
- submitNPS有效期内验证（isValidLicense()链上独立）
- 快速通道冷却期（severity4-5单签24h，severity5多签跳过）
- severity入口检查require(severity>=3 && severity<=5)
- evidenceHash锚定IPFS
- DAO MIN_MEMBERS=11
- 投票权重与势位引擎解耦
- 经济博弈替代KYC：80%基准价约束+自购无退款权
