什么是「势」

Shi —— 东方智慧中的生长动力学

源于易经

「势」不是静态的位置，而是动态的流动。 就像河流中的水，每一刻都在变化，但又有其内在的规律。 64卦不是分类标签，而是描述事物在不同阶段的能量状态。

—— 从潜藏（坤）到爆发（乾），是势能积累与释放的完整周期

三维编织

传统系统用一维指标（如热度、排名）衡量资产。 「势」用三维张量：时间（活跃程度）、 空间（平台分布）、关系（引用网络）。 只有这三个维度的交织，才能完整描述一个资产的生命状态。

—— 单一维度的成功往往是片面的，三维编织呈现全貌

「势」的三重含义

1. 势能（Potential）

资产蕴含的生长可能性。不是现在的价值，而是未来的潜力。

2. 势位（Position）

资产在三维空间中的坐标。时间、空间、关系的交汇点，定义了当前状态。

3. 势场（Field）

影响资产生长的环境力量。边界自适应，阈值动态调整，形成生态张力。

设计哲学

约束不是限制，而是生态的免疫系统

🌱 为什么需要约束？

假设没有约束，创作者可以：

  • × 大成期资产设 衍=0（禁止衍生）— 生态已形成，突然切断关系链
  • × 成熟期设 益=0（锁定收益）— 投资者无法退出
  • × 热门资产随意提高价格10倍 — 用户流失，生态萎缩
  • × 频繁软分叉收割用户 — 信任机制瓦解

✅ 约束保护的是谁？

// 约束 ≠ 剥夺创作者主权
// 约束 = 保护已进入生态的所有参与者
创作者 ──→ 资产 ──→ 用户/衍生者/投资者
│ │ │
└──────────┴────────────┘
↑ 约束保护这层关系

创作者的"绝对自由"会导致公地悲剧——个体理性决策导致集体非理性结果。

约束 ≠ 中心化

这是最关键的澄清。ECHO的约束设计不是平台控制，而是协议规则。

❌ 中心化平台（如抖音）

  • 规则制定：单一实体
  • 规则修改：单方面
  • 执行：中心化服务器
  • 退出：无法选择

✅ ECHO协议

  • 规则制定：开源代码
  • 规则修改：社区投票
  • 执行：分布式节点
  • 退出：可分叉迁移

64卦约束的本质：代码即法律，不是平台政策。它是生态的免疫系统——既保持去中心化，又保护生态健康。

为什么采用BA模式？

完全精确的数据验证在分布式系统中成本极高。BA模式在真实性和可行性之间取得平衡：

  • • 正常创作者无需担心被误判（统计误差在可接受范围）
  • • 刷量行为会被检测并惩罚（系统性异常）
  • • 7天挑战期提供申诉机会（纠错机制）

休眠机制

创作者的保护性权利 —— 在特殊时期暂停约束生效

休眠规则

  • 3 每年最多 3 次
  • 90 每次最长 90 天
  • 🔒 期间势位锁定，约束不生效
  • ⏸️ 已授权用户权益不受影响

适用场景

  • • 创作者需要专注创作，暂时不希望管理生态
  • • 市场环境剧变，需要时间观察再调整策略
  • • 个人原因（健康、家庭等）需要暂时退出
  • • 争议期，需要时间协商解决方案

艮卦对应：当资产进入艮卦（止息期）或创作者主动申请休眠，系统将锁定当前配置，暂停约束计算，为创作者提供喘息空间。

为什么必须允许分叉？

分叉是去中心化协议的终极安全保障。如果创作者认为ECHO协议的约束不再符合其利益，他们可以选择：

  1. 导出所有资产数据和用户关系
  2. 部署自己的协议实例（可以修改或移除约束）
  3. 邀请原生态用户自愿迁移
  4. 原ECHO网络上的资产标记为"已分叉"

这确保了协议层约束不会变成平台层的压迫。

核心算法

// 计算有效配置：创作者意图 ∩ 物理法则
function
calculateEffectivePolicy(
blueprint: Blueprint,
currentShi: Hexagram
): EffectivePolicy {
// 获取当前卦象的约束规则
const rules = HEXAGRAM_RULES[currentShi];
// 计算交集
return {
yong: intersect(blueprint.yong, rules.constraints.yong),
yan: intersect(blueprint.yan, rules.constraints.yan),
kuo: intersect(blueprint.kuo, rules.constraints.kuo),
yi: intersect(blueprint.yi, rules.constraints.yi),
conflicts: detectConflicts(blueprint, rules)
};
}
